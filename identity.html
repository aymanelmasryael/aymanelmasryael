Section 02

Logo System

The AEL mark is a closed modular system on a 7×7 grid. It is never redrawn, never reinterpreted, never stylized.

Construction

The mark is built from 19 identical 32.4-unit squares placed on a strict 7×7 grid. Every square is the same size. Every position is measured. Nothing is drawn freehand.

The composition is not a picture — it is a closed permutation system. Any single square can be relocated to close any empty cell without breaking the mark. This property makes the logo a solvable grid, related in spirit to the modular logic of Superstudio (1969) and Enzo Mari's Autoprogettazione (1974).

Canonical
Extended · preview only
Canonical variant · Approved for production

7×7 construction grid · 19 squares · 1 movable module

Reading the Mark

Three letters emerge from the same grid:

AFormed in negative space at the top-left — an arch carved from a solid block, with a square void completing the counter.
EFormed on the right columns — upper bar, lower bar, and vertical stem. The middle bar is provided by the movable module when it sits at mid-height.
LFormed twice — once as a top strip (Γ shape), once as a lower strip (L shape) — matching the two initials of the owner's name.

The Movable Module

The seven-square strip at the bottom is not decoration. It is a functional key. When moved to mid-height, it simultaneously completes the A crossbar and the E middle bar. This is the operating logic of the mark — the logo is not fixed; it is solvable.

Clear Space & Minimum Sizes

CLEAR SPACE
1 unit = 1 square of the 7×7 grid (32.4 units).
Minimum clear space on all four sides = 1 unit.
At 80px logo: minimum clear space = 11.4px.
MINIMUM SIZES
Digital (screen): 28px height.
Print (offset): 14mm height.
Embroidery: 22mm height.
Favicon: 16px — icon-only variant required.

Correct Usage

DO
Use only the approved SVG. Maintain 1:1 aspect ratio. Apply on black, white, or AEL Blue. Respect clear space. Preserve the 19-square count.
DO NOT
Stretch, rotate, or skew. Apply drop shadows or gradients. Change square colors outside the canonical palette. Remove any square from the grid. Redraw with different grid dimensions.

Section 25

Token Architecture

The code-level layer. Every visual decision in this document resolves to a CSS custom property — compliant with Tailwind v4 and shadcn/ui conventions.

Design Philosophy

One source of truth. AEL tokens are split into three tiers: Primitive (raw palette), Semantic (intent-driven aliases), and Scale (Tailwind v4 compatible scales). Semantic tokens never reference primitives directly — they resolve through the OKLCH color space, allowing automatic gamut mapping and perceptual uniformity across displays. Every OKLCH value ships with a HEX fallback for legacy browsers.

Semantic Token Pairs

Every surface token is paired with its foreground counterpart. This guarantees contrast integrity by design — never by accident.

Glossary

Definitions of key terms used throughout this document. Copy any term for quick reference.

Design Tokens

Token
A named value (color, size, font) stored in a CSS custom property for reuse across components and platforms.
Primitive Token
A raw palette value (e.g., --blue: #0074FF) with no semantic meaning. Never used directly in components.
Semantic Token
An intent-driven alias (e.g., --primary) mapping a primitive to a functional role.
Scale Token
A token following a systematic progression — spacing, typography, radius — often called a "scale".
Semantic Pairing
A surface token paired with its foreground counterpart (e.g., --primary / --primary-foreground) to guarantee contrast.

Color Science

OKLCH
A perceptually uniform color space (Lightness, Chroma, Hue). Modern alternative to HSL. Enables gamut mapping and consistent perception across displays.
Gamut Mapping
Automatic adjustment of out-of-gamut colors to displayable ranges. OKLCH handles this more gracefully than RGB or HSL.
Contrast Ratio
Luminance ratio between two colors. WCAG requires 4.5:1 for body text (AA), 7:1 for AAA.
Hex Fallback
A legacy CSS value (e.g., #FFFFFF) declared before a modern value (e.g., oklch(100% 0 0)) for browser support.

Accessibility

WCAG
Web Content Accessibility Guidelines. WCAG 2.2 AA is the AEL baseline standard.
ARIA
Accessible Rich Internet Applications. Attributes like role, aria-label, aria-live that improve screen reader support.
Landmark
Semantic HTML element or ARIA role (banner, navigation, main, contentinfo) that helps screen readers navigate.
Focus Trap
Keeping keyboard focus inside a modal or dialog while it is open. Required for accessible modals.
prefers-reduced-motion
A CSS media query honoring users who request reduced animation. AEL disables all non-essential motion.

Localization

RTL
Right-to-Left layout for languages like Arabic, Hebrew, and Farsi. Requires logical CSS properties.
LTR
Left-to-Right layout for languages like English, French, and Spanish.
Logical Properties
CSS properties like margin-inline-start that adapt automatically to text direction.

Web & Infrastructure

CDN
Content Delivery Network. Distributes assets globally for faster load times.
DNS
Domain Name System. Translates domain names to IP addresses.
CNAME
Canonical Name record. Maps a subdomain to another domain.
TLS / SSL
Transport Layer Security. Encrypts HTTPS traffic between browser and server.
JSON-LD
JavaScript Object Notation for Linked Data. Structured data that search engines read.
Static Site
A site served as pre-built HTML/CSS/JS without server-side runtime.

Versioning & Process

SemVer
Semantic Versioning. MAJOR.MINOR.PATCH (e.g., 5.3.0) for predictable releases.
Conventional Commits
A commit message convention (feat:, fix:, docs:) enabling automated changelogs.
Changelog
A curated, human-readable record of changes for each release. See Section 26.
Pull Request
A proposed change to the codebase. See Section 31 for the review checklist.

Design System Terms

Design System
A collection of reusable components, tokens, and guidelines that form the visual and functional foundation of a brand.
Component Primitive
A foundational UI element (button, input, tag) with variants and states defined by tokens.
Golden Ratio
The proportion 1:1.618, used in Gridi and various AEL layouts for proportional harmony.
Modular Grid
A grid combining columns and rows into modules. Underpins the AEL logo system (7×7).

Frequently Asked Questions

Common questions about the AEL Brand & Operating System. If your question is not answered here, open an issue on GitHub.

About the System

What is the AEL Brand & Operating System?
It is a complete, open-source system documenting every aspect of the AEL Digital Studio brand — identity, logo, color, typography, components, voice, motion, accessibility, and design tokens. It serves as the single source of truth for anyone building with or learning from the AEL brand.
Who is this system for?
Designers, developers, brand strategists, AI engineers, and students. Anyone who needs a reference for how a modern, systematic brand should be documented and implemented.
Why publish this publicly?
Three reasons: (1) Transparency builds trust. (2) Open systems improve faster through community feedback. (3) The design community benefits from real, production-grade examples — not toy demos.
Is the AEL logo available for reuse?
The logo files are visible for reference, but commercial use of the AEL brand requires written permission. The code and documentation are open; the brand identity is not. Contact ayman@aymanelmasry.me for licensing.

Usage & Licensing

Can I use the token architecture in my own project?
Yes. The code is MIT-licensed and the documentation is CC BY 4.0. You may fork, adapt, and use the token architecture in your own projects with attribution. Keep the attribution notice and, if practical, link back to this document.
Can I use this as a template for my own brand system?
Absolutely. The structure, semantic token conventions, and section organization are generic by design. Replace the AEL colors, logo, and content with yours. Keep the MIT/CC BY attribution for the code and documentation structure.
What is the difference between MIT and CC BY 4.0?
MIT covers code — HTML, CSS, JavaScript. CC BY 4.0 covers documentation, guidelines, and specifications. Both require attribution; neither requires you to share your modifications under the same license.

Technical Details

Is the system compatible with Tailwind and shadcn/ui?
Yes. All semantic tokens follow shadcn/ui naming conventions (--background, --foreground, --primary, etc.), and the scale tokens match Tailwind v4's --text-* and --spacing conventions. You can drop the :root block directly into any Tailwind v4 project.
Why use OKLCH instead of HEX or HSL?
OKLCH is perceptually uniform — a lightness change of 10% looks like 10% regardless of hue. It also enables automatic gamut mapping. This produces more consistent colors across displays and brand touchpoints. Every OKLCH value here has a HEX fallback for legacy browsers.
Does it support Arabic / RTL layouts?
Yes. Section 23 demonstrates RTL layouts side-by-side with LTR. The token system is direction-agnostic and works with both dir="rtl" and dir="ltr". All margins and paddings use logical properties where relevant.
How do I export tokens for Figma or Style Dictionary?
Click the export button in the top toolbar (the download icon). This generates a W3C Design Tokens JSON file compatible with Figma Tokens, Tokens Studio, and Style Dictionary. See Section 25 for the raw CSS.

Contributing & Roadmap

How can I contribute?
See Section 31 — Contributing. We welcome bug reports, feature requests, documentation improvements, translations, and new design tokens. Open an issue or submit a PR on GitHub.
Is there an npm package?
Not yet. @ael/tokens is on the Q3 2025 roadmap. Watch the repository for updates or subscribe to the RSS feed.
How often is the system updated?
We follow Semantic Versioning. MAJOR versions (breaking) are rare and announced in advance. MINOR versions (new features) ship roughly quarterly. PATCH versions (fixes) ship as needed. See Section 26 — Changelog for full history.
