Section 02

Logo System

The AEL logo is a modular geometric mark. It is never redrawn, never reinterpreted, never stylized.

Logo Meaning

The logo is built from a 7x7 square grid. The top segment forms the letter "A" through negative space — a curved arch carved from a solid block. The bottom segment is a matrix of 4x4 blue squares representing structured intelligence, modular systems, and computational precision.

Primary Logo

Dark background · Blue background · Light background

Safe Area

Safe area = 50% of logo height on all sides. Minimum size: 24px digital, 8mm print.

Correct Usage

DO
Use only the approved SVG. Maintain aspect ratio. Apply on black, white, or AEL Blue.
DO NOT
Stretch, rotate, or skew. Apply drop shadows or gradients. Change blue squares to another color.

Section 25

Token Architecture

The code-level layer. Every visual decision in this document resolves to a CSS custom property — compliant with Tailwind v4 and shadcn/ui conventions.

Design Philosophy

One source of truth. AEL tokens are split into three tiers: Primitive (raw palette), Semantic (intent-driven aliases), and Scale (Tailwind v4 compatible scales). Semantic tokens never reference primitives directly — they resolve through the OKLCH color space, allowing automatic gamut mapping and perceptual uniformity across displays.

Semantic Token Pairs

Every surface token is paired with its foreground counterpart. This guarantees contrast integrity by design — never by accident.

Section 29

Glossary

Definitions of key terms used throughout this document.

Token
A named value (color, size, font) stored in a CSS custom property for reuse.
Primitive Token
A raw palette value (e.g., --blue: #0074FF) with no semantic meaning.
Semantic Token
An intent-driven alias (e.g., --primary) mapping a primitive to a role.
Scale Token
A token following a systematic progression (spacing, typography, radius).
OKLCH
A perceptually uniform color space (Lightness, Chroma, Hue). Modern alternative to HSL.
WCAG
Web Content Accessibility Guidelines. WCAG 2.2 AA is our baseline standard.
ARIA
Accessible Rich Internet Applications. Attributes that improve screen reader support.
RTL
Right-to-Left layout for languages like Arabic, Hebrew, and Farsi.
LTR
Left-to-Right layout for languages like English, French, and Spanish.
CDN
Content Delivery Network. Distributes assets globally for faster load times.
JSON-LD
JavaScript Object Notation for Linked Data. Structured data for search engines.
SEO
Search Engine Optimization. Practices that improve search visibility.
TTL
Time To Live. Duration DNS records are cached by resolvers.
DNS
Domain Name System. Translates domain names to IP addresses.
CNAME
Canonical Name record. Maps a subdomain to another domain.
SSL / TLS
Secure Sockets Layer / Transport Layer Security. Encrypts HTTPS traffic.
Static Site
A site served as pre-built HTML/CSS/JS, without a server-side runtime.
CDN Edge
Geographically distributed servers that cache and serve content closer to users.
SemVer
Semantic Versioning. MAJOR.MINOR.PATCH (e.g., 5.0.0) for predictable releases.
Conventional Commits
A commit message convention (feat:, fix:, docs:) enabling automation.
Section 30

Frequently Asked Questions

Common questions about the AEL Brand & Operating System.

What is the AEL Brand & Operating System?
It is a complete, open-source system documenting every aspect of the AEL Digital Studio brand — identity, logo, color, typography, components, voice, motion, accessibility, and design tokens. It serves as the single source of truth for anyone building with the AEL brand.
Can I use this system for my own project?
Yes. The code is MIT-licensed and the documentation is CC BY 4.0. You may fork, adapt, and use the token architecture in your own projects with attribution. You may not use the AEL logo or claim the brand as your own.
How do I contribute?
See our Contributing section and CONTRIBUTING.md. We welcome bug reports, feature requests, documentation improvements, and design token additions.
Is the system compatible with Tailwind and shadcn/ui?
Yes. All semantic tokens follow shadcn/ui naming conventions, and the scale tokens match Tailwind v4's --text-* and --spacing conventions. You can drop the :root block directly into any Tailwind v4 project.
How is accessibility handled?
We conform to WCAG 2.2 Level AA. The system supports keyboard navigation, screen readers, reduced motion, high contrast, and both light and dark themes. See Section 28 for the full statement.
Does it support Arabic / RTL layouts?
Yes. Section 23 demonstrates RTL layouts side-by-side with LTR. The token system is direction-agnostic and works with both dir="rtl" and dir="ltr".
How often is the system updated?
We follow Semantic Versioning. MAJOR versions (breaking) are rare; MINOR versions (new features) ship roughly quarterly; PATCH versions (fixes) ship as needed. See Changelog.
Can I request a new feature or report a bug?
Absolutely. Open an issue on GitHub Issues. Use the Bug Report or Feature Request template.
How do I export tokens for Figma or other tools?
Section 25 provides a raw CSS block. Use the "Export as JSON" button to download the full token set in W3C Design Tokens format, compatible with Figma Tokens, Style Dictionary, and Tokens Studio.
Is there an API or npm package?
Not yet. @ael/tokens is on the Q3 2025 roadmap. See ROADMAP.md.
